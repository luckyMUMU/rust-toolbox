# 工作流模块设计文档

## 概述

工作流模块是系统的核心组件，负责工作流的定义、验证、调度和执行。该模块采用有向无环图(DAG)结构来表示工作流，支持条件分支、循环、并行执行等复杂逻辑。

## 架构设计

### 模块结构

```
src/workflow/
├── mod.rs              # 模块导出
├── definition.rs       # 工作流定义数据结构
├── validator.rs        # 工作流验证器
├── scheduler.rs        # DAG调度器
├── engine.rs          # 工作流执行引擎
└── execution.rs       # 执行状态管理
```

### 核心组件

1. **WorkflowDefinition**: 工作流定义的数据模型
2. **WorkflowValidator**: 工作流语法和语义验证器
3. **DagScheduler**: 基于petgraph的DAG调度器
4. **WorkflowEngine**: 工作流执行引擎接口
5. **ExecutionManager**: 执行状态和生命周期管理

## 数据结构设计

### WorkflowDefinition

工作流定义包含以下核心元素：

- **基本信息**: 名称、版本、描述、元数据
- **节点集合**: 工作流中的所有节点
- **边集合**: 节点间的依赖关系
- **全局配置**: 超时、重试策略、并发限制等

### WorkflowNode

工作流节点支持多种类型：

- **Tool**: 工具节点，执行具体的工具
- **Condition**: 条件节点，根据条件选择执行路径
- **Loop**: 循环节点，重复执行子工作流
- **Parallel**: 并行节点，并发执行多个子任务
- **Checkpoint**: 检查点节点，保存执行状态

### WorkflowEdge

工作流边定义节点间的依赖关系：

- **from/to**: 源节点和目标节点ID
- **condition**: 可选的条件表达式
- **weight**: 边的权重（用于优先级排序）

## 验证器设计

### 语法验证

- 节点ID唯一性检查
- 边的有效性检查（源节点和目标节点存在）
- 必填字段完整性检查
- 数据类型正确性验证

### 语义验证

- DAG结构验证（无环检查）
- 依赖关系一致性检查
- 工具节点可用性验证
- 参数模式匹配验证

### 依赖关系检查

- 强依赖：必须等待前置节点完成
- 弱依赖：可以并行执行，但需要前置节点的输出
- 条件依赖：根据条件决定是否依赖

## 调度器设计

### DAG构建

使用petgraph库构建有向图：

```rust
use petgraph::{Graph, Directed};
use petgraph::graph::{NodeIndex, EdgeIndex};

type WorkflowGraph = Graph<WorkflowNode, WorkflowEdge, Directed>;
```

### 拓扑排序

- 使用Kahn算法进行拓扑排序
- 支持并行节点的同时调度
- 处理条件分支的动态路径选择

### 执行顺序优化

- 关键路径优先调度

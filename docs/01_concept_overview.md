# Workflow Toolkit - 核心概念

> **L1: 核心概念层 (Concept Layer)**
> 
> 一句话定义：Workflow Toolkit 是一个**工具能力编排与复用平台**，通过对工具的工作流编排实现固定流程的复用，支持AGENT动态扩展能力构建复杂功能，同时提供CLI/TUI接口让人类用户便捷调用并监测运行状况。

---

## 1. 核心痛点

### 1.1 当前痛点

#### 工具使用层面
- **工具碎片化**：工具分散在各处，缺乏统一发现和调用机制
- **流程难复用**：固定处理流程无法固化复用，重复开发成本高
- **AGENT能力受限**：AI Agent只能调用单工具，难以组合构建复杂功能

#### 技术实现层面
- **性能瓶颈**：Python/Node.js 实现的引擎难以处理高并发场景
- **扩展困难**：插件系统封闭，难以集成多语言生态
- **AI 集成弱**：缺乏与 LLM 原生的交互协议支持
- **可观测性差**：执行状态不透明，难以调试和监控

### 1.2 我们的解决方案

| 痛点 | 解决方案 |
|------|----------|
| 工具碎片化 | 统一工具注册中心，标准化工具定义和发现机制 |
| 流程难复用 | 工作流编排固化流程，支持版本管理和模板复用 |
| AGENT能力受限 | 动态编排能力，支持工具组合构建复杂函数效果 |
| 性能瓶颈 | Rust + Tokio 异步运行时，微秒级调度延迟 |
| 扩展困难 | 多语言插件系统（Native/Python/Node.js/Docker） |
| AI 集成弱 | 原生 MCP (Model Context Protocol) 支持 |
| 可观测性差 | TUI 实时监控 + LanceDB 时间旅行查询 |

---

## 2. 核心价值主张

### 2.1 工具编排复用
- 工作流编排固化固定处理流程
- 一次定义，多次复用，降低重复开发成本
- 支持版本管理和模板共享

### 2.2 AGENT能力扩展
- 动态编排让AGENT突破单工具限制
- 支持工具组合构建复杂函数效果
- 既支持调用编排后的工作流，也支持调用单独工具

### 2.3 人机双模式
- **AGENT模式**：通过MCP协议标准化调用
- **人类模式**：CLI/TUI双接口便捷操作
- 统一的工具发现和使用体验

### 2.4 开发者友好
- **脚本化编排**：YAML/JSON简单定义，直观易懂，易于版本控制
- **多语言插件**：Python/Node.js/Rust SDK支持，复用现有代码生态
- **基础设施开放**：存储、缓存、配置、日志等能力开放给插件开发者

### 2.5 运行监测
- TUI实时监控执行状况
- 全面的执行审计日志
- 性能指标和系统资源监控

### 2.6 高性能
- 基于 Rust 零成本抽象
- 真正的并行执行（非并发）
- 单机支持 100+ 并发工作流

### 2.7 模块化
- 核心引擎与业务逻辑分离
- 插件化架构，无限扩展
- DDD 分层设计，高内聚低耦合

### 2.8 可靠性
- 内置检查点与自动重试
- 事务性状态管理
- 全面的审计日志

### 2.9 AI 就绪
- MCP 协议原生支持
- 上下文管理与 Token 计数
- 流式响应支持

## 3. 关键术语

| 术语 | 定义 |
|------|------|
| **Workflow** | 一组有序的任务集合，由 DAG 定义 |
| **Tool** | 可执行的最小单元，完成特定功能 |
| **Plugin** | 一组工具的集合，提供特定扩展能力 |
| **Component** | 工作流节点组件，LiteFlow 风格 |
| **Data Slot** | 数据交换上下文（工作台模式） |
| **Executor Chain** | 执行器责任链（Audit → Cache → Retry → Basic） |
| **MCP** | Model Context Protocol，AI 交互协议 |

---

## 4. 适用场景

- **AI Agent 编排**：多步骤 LLM 调用、工具使用、决策流程
- **ETL 数据管道**：复杂依赖关系和数据转换
- **自动化运维**：并行执行多服务器任务
- **文件管理**：智能分类、批量处理、人工确认

## 1. ADR 概述

架构决策记录 (Architecture Decision Record, ADR) 是记录重要架构决策的文档。每个 ADR 描述：
- **背景**: 为什么需要做这个决策
- **决策**: 做了什么决策
- **影响**: 这个决策带来的影响

### 2.2 ADR 详情

#### ADR-DI-001: 自建 DI 容器而非使用 shaku 框架

**决策**: 继续使用自建 DI 容器，不引入 shaku 或其他第三方 DI 框架。

**理由**:
- 自建方案已满足当前需求
- 完全可控、无额外依赖、可定制化
- 团队无需学习新框架，降低认知负担

**影响**:
- ✅ 完全掌控 DI 实现
- ✅ 无额外依赖
- ⚠️ 需要自行维护和测试

**相关文档**: [adr/adr-di-001-di-container.md](adr/adr-di-001-di-container.md)

---

#### ADR-Workflow-002: 采用 JoinSet 替代 join_all 进行并行执行

**决策**: 使用 `tokio::task::JoinSet` 替代 `futures::future::join_all`。

**理由**:
- 支持 `abort()` 取消单个任务
- 支持 `shutdown()` 取消所有任务
- 支持 `join_next()` 按完成顺序处理
- 支持 `AbortHandle` 获取任务句柄

**影响**:
- ✅ 支持任务取消
- ✅ 支持失败快速终止
- ✅ 更好的错误处理和恢复能力
- ⚠️ 需要重构现有并行执行代码

**相关文档**: [adr/adr-workflow-002-joinset.md](adr/adr-workflow-002-joinset.md)

---

#### ADR-Plugin-003: WASM 插件沙箱隔离策略

**决策**: 采用多层次沙箱隔离策略。

**安全级别**:
- `Unrestricted`: 无限制 - 仅用于信任模块
- `Basic`: 基础隔离 - 限制文件系统和网络
- `Strict`: 严格隔离 - 禁止所有外部访问
- `Maximum`: 最大隔离 - 额外限制 CPU 和内存

**影响**:
- ✅ 多层次安全防护
- ✅ 灵活的安全级别配置
- ✅ 完整的审计日志
- ⚠️ 增加实现复杂度

**相关文档**: [adr/adr-plugin-003-wasm-sandbox.md](adr/adr-plugin-003-wasm-sandbox.md)

---

#### ADR-Tools-004: 工具 Schema 验证策略

**决策**: 采用基于 jsonschema 库的 Schema 验证系统。

**理由**:
- jsonschema 库是 Rust 生态中成熟的 JSON Schema 验证库
- 支持完整的 JSON Schema 规范
- 性能好、社区活跃

**影响**:
- ✅ 完整的 JSON Schema 支持
- ✅ 清晰的中文错误消息
- ✅ Schema 编译缓存提高性能
- ⚠️ 额外依赖 jsonschema 库

**相关文档**: [adr/adr-tools-004-schema-validation.md](adr/adr-tools-004-schema-validation.md)

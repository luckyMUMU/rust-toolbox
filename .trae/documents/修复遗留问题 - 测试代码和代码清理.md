# 修复遗留问题计划

## 阶段一：修复测试代码类型问题 (高优先级)

### 任务 1.1: 修复 nodejs_tests.rs 中的类型问题
- 文件: `src/plugins/nodejs_tests.rs`
- 问题: `ToolInput` 和 `ToolOutput` 类型不匹配
- 修复: 更新测试代码使用正确的类型

### 任务 1.2: 修复 registry.rs 测试中的 NativeTool 创建
- 文件: `src/tools/registry.rs`
- 问题: `NativeTool` 结构体字段不匹配
- 修复: 使用 `NativeTool::new()` 构造函数

### 任务 1.3: 修复其他测试文件中的类似问题
- 检查并修复所有测试中的类型不匹配

## 阶段二：清理未使用导入 (中优先级)

### 任务 2.1: 自动修复未使用导入
```bash
cargo fix --lib -p workflow-toolkit
```

### 任务 2.2: 手动检查并修复剩余问题
- 检查每个模块的导入语句
- 移除真正未使用的导入

## 阶段三：死代码清理 (中优先级)

### 任务 3.1: 识别死代码
- 使用 `cargo deadlinks` 或 IDE 分析
- 标记未使用的字段、方法、结构体

### 任务 3.2: 安全移除死代码
- 移除确认未使用的代码
- 保留可能用于未来扩展的代码（添加注释说明）

## 阶段四：验证 (关键)

### 任务 4.1: 编译验证
```bash
cargo check --lib
cargo clippy -- -D warnings
```

### 任务 4.2: 测试验证
```bash
cargo test --lib
```

### 任务 4.3: 格式化检查
```bash
cargo fmt --check
```

## 预期结果

1. 所有测试通过
2. 编译警告大幅减少
3. 代码库更加整洁
4. 提高代码可维护性

## 风险自审

1. **测试修复**: 可能引入新的问题，需要仔细验证
2. **导入清理**: 某些导入可能在宏中使用，需要特别注意
3. **死代码**: 确保不误删实际使用的代码

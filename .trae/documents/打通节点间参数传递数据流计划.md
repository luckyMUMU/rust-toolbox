# 打通节点间参数传递数据流

我们将实现基于模板引擎的参数解析机制，使工作流节点能够引用上游节点的执行结果和全局变量。

## 1. 核心变更 (Core Changes)

### 1.1 集成模板引擎
在 `DefaultWorkflowEngine` 中引入 `TemplateEngine`，用于处理参数中的变量替换。

- **修改文件**: `src/workflow/engine.rs`
- **变更点**:
    - 在 `DefaultWorkflowEngine` 结构体中添加 `template_engine: Arc<TemplateEngine>` 字段。
    - 更新 `new`, `new_with_cache`, `new_with_audit` 等构造函数以初始化 `TemplateEngine`。

### 1.2 实现参数解析逻辑
在 `DefaultWorkflowEngine` 中新增 `resolve_parameters` 方法。

- **逻辑**:
    1. 创建 `TemplateContext`。
    2. **注入节点结果**: 遍历 `WorkflowExecution.node_states`，将已完成节点的结果注入到 `nodes` 命名空间（例如 `${nodes.step1.some_output}`）。
    3. **注入全局变量**: 合并 `ExecutionContext.global_variables` 和 `WorkflowExecution.global_context` 到上下文。
    4. 调用 `template_engine.expand` 解析节点定义的 `parameters`。

### 1.3 更新节点执行签名
重构 `execute_node` 和 `execute_node_with_retry` 方法，使其接收完整的 `WorkflowNode` 定义而非仅 `node_id`。

- **旧签名**: `fn execute_node(..., node_id: &str, ...)`
- **新签名**: `fn execute_node(..., node: &WorkflowNode, ...)`
- **优势**: 直接访问节点的 `parameters` 和 `retry_policy`，消除重复查找和 TODO 代码。

## 2. 详细实施步骤 (Implementation Steps)

1.  **修改结构体**: 更新 `DefaultWorkflowEngine` 定义及构造函数。
2.  **实现 `resolve_parameters`**:
    ```rust
    fn resolve_parameters(&self, node: &WorkflowNode, execution: &WorkflowExecution, context: &ExecutionContext) -> Result<Value>
    ```
3.  **重构执行方法**:
    - 更新 `execute_node_with_retry` 接收 `&WorkflowNode`。
    - 在方法内部调用 `resolve_parameters` 获取解析后的参数。
    - 将解析后的参数传递给 `tool_registry.execute_tool`。
4.  **更新调用点**: 修改 `execute_workflow` 中的循环逻辑，从 `definition` 获取节点实例并传递给执行方法。
5.  **清理 TODO**: 移除 `engine.rs` 中关于 "resolve parameters" 的临时代码 (`Value::Null`)。

## 3. 数据流示例 (Data Flow Example)

假设节点 A (`step1`) 输出 `{ "file_path": "/tmp/data.txt" }`。
节点 B (`step2`) 定义参数：
```json
{
  "path": "${nodes.step1.file_path}",
  "mode": "read"
}
```
执行节点 B 时，`resolve_parameters` 将解析出：
```json
{
  "path": "/tmp/data.txt",
  "mode": "read"
}
```
并将其传递给工具执行。

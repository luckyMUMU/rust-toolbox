# 修复工具列表未显示的问题

## 问题分析
经过代码分析，确认以下原因导致了您遇到的问题：
1. **工具未注册**：`file-management` 插件虽然代码已实现，但在 `src/main.rs` 的主程序启动逻辑中**未被初始化和注册**。因此，`tool list` 只能看到硬编码的 `echo` 工具。
2. **"Registered 11 MCP tools" 误导**：这条日志指的是 MCP 服务内部的 10 个管理工具（如 `list_tools`, `install_plugin` 等）加上 1 个 `echo` 工具，并非指文件管理工具。
3. **Workflow 列表为空**：`workflow list` 命令的实现目前是一个占位符（Placeholder），代码中明确注释了 `TODO: Implement proper workflow listing`，且未扫描 `examples/templates` 目录。

## 实施计划

我将修改 `src/main.rs` 以手动注册文件管理插件，使其工具能被加载。

### 1. 修改 `src/main.rs`
- **引入依赖**：引入 `FileManagementPlugin` 和 `Plugin` trait。
- **初始化插件**：在创建 `tool_registry` 后，实例化 `FileManagementPlugin`。
- **配置插件**：创建一个默认的 `PluginConfig` 并调用 `initialize`。
- **注册工具**：通过 `get_tools()` 获取文件管理工具，并将它们注册到 `BasicToolRegistry` 中。

### 2. 预期结果
- 再次运行 `tool list` 时，应能看到 `file-mover`, `folder-classifier`, `batch-processor` 等所有文件管理工具。
- 用户将能够通过 `workflow execute` 命令运行 YAML 工作流（因为工具已就绪）。
- `workflow list` 暂时仍为空（这是预期行为，直至实现持久化存储或目录扫描），但我会修复核心的工具可用性问题。

### 3. 代码变更预览
```rust
// 在 main.rs 中添加
use workflow_toolkit::plugins::{FileManagementPlugin, Plugin, PluginConfig};
use workflow_toolkit::core::PluginType;

// ... 在 tool_registry 创建后 ...
let mut fm_plugin = FileManagementPlugin::new();
let config = PluginConfig::new("file-management".to_string(), PluginType::Native);
fm_plugin.initialize(config)?;

for tool in fm_plugin.get_tools() {
    tool_registry.register_tool(tool)?;
}
```

# 代码库编译修复计划

## 问题概述

当前代码库存在 **139 个编译错误** 和 **67 个警告**，主要分为以下几类：

## 错误分类

### 1. ExecutorType 缺少 Hash trait (3 处)
**文件**: `src/tools/external/mod.rs`
**问题**: `ExecutorType` 枚举用作 HashMap 的 key，但未实现 `Hash` trait
**修复**: 添加 `#[derive(Hash)]`

### 2. Middleware 类型不匹配 (5 处)
**文件**: `src/tools/executor.rs`, `src/tools/middleware.rs`
**问题**: `MiddlewareStackBuilder::with()` 期望 `Arc<dyn Middleware>`，但调用时传入具体类型
**修复**: 
- 添加 `with_boxed()` 方法接受具体类型并自动包装为 `Arc`
- 或修改调用处使用 `Arc::new()` 包装

### 3. workflow_id 字段访问错误 (3 处)
**文件**: `src/tools/external/python.rs`, `nodejs.rs`, `docker.rs`
**问题**: `workflow_id` 是字段而非方法，不应使用 `()` 调用
**修复**: 移除 `()` 改为字段访问 `ctx.workflow_id`

### 4. jsonschema API 变更 (多处)
**文件**: `src/tools/schema_validator.rs`
**问题**: 
- `instance_path()` 和 `instance()` 现在是字段而非方法
- 错误类型变体 (Type, Required, Minimum 等) 不再作为枚举变体存在
**修复**: 
- 移除方法调用的 `()`
- 简化错误类型匹配逻辑，移除不存在的变体匹配

### 5. 其他错误
- 缺少字段 `metadata` 在某些结构体
- 生命周期参数问题
- 类型推断失败
